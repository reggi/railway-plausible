# Plausible Community Edition on Railway

Reproducible Railway infrastructure for self-hosting
[Plausible Community Edition](https://github.com/plausible/community-edition).

The entire service topology is declared in
[`.railway/railway.ts`](.railway/railway.ts). No application fork is required:
the deployment uses pinned upstream container images and Railway-managed
PostgreSQL.

The project uses Railway's official TypeScript SDK and requires Node.js 22 or
newer and Railway CLI 5.42.1 or newer.

## Architecture

| Service      | Image                                            |   Port | Health check    | Persistence                             |
| ------------ | ------------------------------------------------ | -----: | --------------- | --------------------------------------- |
| Plausible CE | `ghcr.io/plausible/community-edition:v3.2.1`     | `8000` | `/api/health`   | Ephemeral                               |
| PostgreSQL   | Railway-managed PostgreSQL                       | `5432` | Railway-managed | Railway-managed                         |
| ClickHouse   | `clickhouse/clickhouse-server:24.12.6.70-alpine` | `8123` | `/ping`         | 1.25 GB volume at `/var/lib/clickhouse` |

Only Plausible is exposed publicly. Both databases remain on Railway's private
network. Railway sleep mode is enabled for Plausible to reduce idle compute
usage; incoming analytics or dashboard requests wake it automatically. Each
deployment supplies its own public hostname through `PLAUSIBLE_DOMAIN`.
Image tags and immutable digests are recorded in
[`.railway/docker-images.json`](.railway/docker-images.json).

## Configuration

Copy `.env.example` to `.env` and replace the example domain before planning:

| Input                       | Required    | Secret | Purpose                                                        | Safe example                                   |
| --------------------------- | ----------- | ------ | -------------------------------------------------------------- | ---------------------------------------------- |
| `PLAUSIBLE_DOMAIN`          | Yes         | No     | Public hostname without a scheme, path, or whitespace          | `analytics.example.net`                        |
| `PLAUSIBLE_SECRET_KEY_BASE` | First apply | Yes    | Unique application signing secret containing at least 64 bytes | Generate locally; do not copy an example value |

The IaC supplies these service variables:

| Variable                     | Service    | Required | Secret | Source                               | Purpose                                                                   | Example                                                       |
| ---------------------------- | ---------- | -------- | ------ | ------------------------------------ | ------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `BASE_URL`                   | Plausible  | Yes      | No     | Derived from `PLAUSIBLE_DOMAIN`      | Public HTTPS origin                                                       | `https://analytics.example.net`                               |
| `CLICKHOUSE_DATABASE_URL`    | Plausible  | Yes      | No     | ClickHouse private-domain reference  | Analytics database connection                                             | `http://clickhouse.railway.internal:8123/plausible_events_db` |
| `DATABASE_URL`               | Plausible  | Yes      | Yes    | PostgreSQL resource reference        | Accounts and application database connection                              | Generated by Railway                                          |
| `DISABLE_REGISTRATION`       | Plausible  | Yes      | No     | Literal `false`                      | Allows initial account registration                                       | `false`                                                       |
| `ENABLE_EMAIL_VERIFICATION`  | Plausible  | Yes      | No     | Literal `false`                      | Disables verification when no mail service is configured                  | `false`                                                       |
| `PORT`                       | Plausible  | Yes      | No     | Literal `8000`                       | HTTP listening port                                                       | `8000`                                                        |
| `SECRET_KEY_BASE`            | Plausible  | Yes      | Yes    | Sealed user input, then `preserve()` | Signs sessions and application data                                       | Never committed                                               |
| `TMPDIR`                     | Plausible  | Yes      | No     | Literal `/tmp`                       | Writable temporary directory                                              | `/tmp`                                                        |
| `CLICKHOUSE_CONFIG_OVERRIDE` | ClickHouse | Yes      | No     | Derived IaC value                    | Disables high-volume diagnostic tables and sets information-level logging | Generated by the IaC                                          |
| `CLICKHOUSE_SKIP_USER_SETUP` | ClickHouse | Yes      | No     | Literal `1`                          | Uses the image's default local user setup                                 | `1`                                                           |
| `PORT`                       | ClickHouse | Yes      | No     | Literal `8123`                       | HTTP listening and health-check port                                      | `8123`                                                        |

Registration is enabled and email verification is disabled by default. Change
those settings in `.railway/railway.ts` before planning if the deployment
requires different behavior.

## Persistence and backups

PostgreSQL stores accounts, sites, and application configuration. The
`clickhouse-data` volume stores analytics events. The Plausible application
service itself is ephemeral.

The ClickHouse service disables high-volume internal metric, trace, processor,
and text log tables and lowers server logging to `information`. The upstream
defaults can otherwise consume roughly 100 MiB per day even with negligible
analytics traffic. The intentionally small 1.25 GB volume includes a recovery
buffer for ClickHouse maintenance operations.

This repository does not automate backups. Configure Railway backups for
PostgreSQL and maintain a separate backup or snapshot of the ClickHouse volume
before upgrades or destructive changes. A restore should use a fresh
PostgreSQL database or ClickHouse volume, validate row counts and
`/api/health`, and only then receive production traffic. Test that procedure
before depending on the backups.

To expand ClickHouse storage, increase `sizeMB` for `clickhouse-data` in
`.railway/railway.ts`, review `railway config plan`, and explicitly approve the
apply. Railway volumes can be expanded without replacing analytics data but
cannot be reduced in place.

## Upgrades

Plausible `v3.2.1` and ClickHouse `24.12.6.70-alpine` are pinned by tag and
digest in `.railway/docker-images.json`. Update one image at a time, verify the
new digest from the official registry, read the upstream release and migration
notes, and back up persistent data before running `railway config plan`.
Explicitly approve `railway config apply` only after reviewing a
non-destructive plan.
